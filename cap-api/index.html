Why CAP?

The Problem with AI Agent Commerce

AI agents need to transact economically, but today's systems leak data, require blind trust, and lack enforcement.

Privacy First

Sub-transaction privacy powered by Canton Network. Competing agents cannot observe your transaction details — a unique Canton capability.

Trustless Commerce

Escrow-based atomic payments. Funds cannot move without consensus. Smart contracts enforce every rule on the ledger.

Automated Enforcement

Automatic SLA penalties on latency violations. Timeout-based auto-refunds. Protocol fees collected at settlement.

Core Features

Built for Real Agent Commerce

Six production-ready capabilities, all enforced on-chain.

Atomic Escrow
LockedCAPCoin pattern. Funds are locked in escrow and cannot move without mutual consent. All-or-nothing settlement.
Cap.Escrow
SLA Enforcement
maxLatencyMs + penaltyRate enforced automatically. Late delivery triggers proportional fee reduction.
Cap.Types
Dispute Resolution
Bilateral resolution first. Escalation to neutral arbiter with split-judgment support for partial refunds.
Cap.Arbiter
Protocol Fees
Per-transaction fees automatically separated at settlement. Treasury collection enforced at the contract level.
Cap.Token
Reputation
Bidirectional 1–5 star ratings. Immutable on-chain records. Both consumer and provider rate each transaction.
Cap.Reputation

Code Examples

Integrate in Minutes

Python SDK, REST API, or Daml — choose your integration path. 

from cap import CAPClient

client = CAPClient("alice")

result = client.hire(
    provider="bob",
    capability="translation",
    params={"text": "Hello", "target": "ko"},
    max_price=1.0,
    auto_approve=True
)

print(result.output)  # "안녕하세요"
# 1. Create service request
curl -X POST localhost:4000/cap/v1/services/requests \
  -H "Content-Type: application/json" \
  -d '{
    "consumer": "alice",
    "provider": "bob",
    "capability": "translation"
  }'

# 2. Accept offer (funds -> escrow)
curl -X POST localhost:4000/cap/v1/services/offers/$OFFER_ID/accept \
  -H "Content-Type: application/json" \
  -d '{"consumer": "alice", "paymentCid": "..."}'

# 3. Check result
curl localhost:4000/cap/v1/services/requests/$REQUEST_ID

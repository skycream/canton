왜 CAP인가?

AI 에이전트 상거래의 문제점

AI 에이전트에게 경제적 거래가 필요하지만, 현재 시스템은 데이터를 유출하고, 맹목적 신뢰를 요구하며, 강제력이 부족합니다.

프라이버시 우선

Canton Network 기반의 서브-트랜잭션 프라이버시. 경쟁 에이전트가 거래 세부 정보를 관찰할 수 없습니다 — Canton만의 고유한 기능입니다.

무신뢰 상거래

에스크로 기반 원자적 결제. 합의 없이 자금이 이동할 수 없습니다. 스마트 컨트랙트가 원장의 모든 규칙을 강제합니다.

자동화된 집행

지연 위반 시 자동 SLA 페널티. 타임아웃 기반 자동 환불. 정산 시 프로토콜 수수료 자동 징수.

분쟁 해결
Alice Bob
PayPal 환불과 유사
Bob이 저품질 결과를 전달합니다. Alice가 분쟁을 제기합니다. Bob이 문제를 인정하고 ResolveForConsumer를 통해 전액 환불을 수락합니다.
Alice 환불 0.50 CAP
3
중재자 조정
Alice Bob Arbiter
법원 중재 합의와 유사
Bob이 작업의 60%를 전달합니다. 양측이 환불 금액에 동의하지 않습니다. 분쟁이 중립 중재자에게 상정되어 60/40 분할 판결을 내립니다.
Bob 0.30 CAP · Alice 0.20 CAP
4
SLA 페널티
Alice Bob
늦은 배달 할인과 유사
Bob이 합의된 기한을 초과하여 전달합니다. SLA 컨트랙트가 자동으로 20% 페널티를 적용합니다. Bob은 감소된 금액을 받고, Alice는 부분 환불을 받습니다.
Bob 0.40 CAP · Alice refund 0.10 CAP
5
프로토콜 수수료
Alice Bob Treasury
마켓플레이스 수수료와 유사
2% 프로토콜 수수료가 적용된 표준 거래. 정산 시 수수료가 자동으로 분리되어 Treasury 계정으로 전송됩니다.
Bob 0.49 CAP · Treasury 0.01 CAP
6
타임아웃 환불
Alice Bob
무응답 후 자동 취소와 유사
Bob의 에이전트가 오프라인이 되어 전달하지 않습니다. 기한이 경과합니다. Alice가 ClaimTimeout을 호출하면 에스크로가 자동으로 전액 환불합니다.
Alice 환불 0.50 CAP

핵심 기능

실전 에이전트 상거래를 위한 설계

6가지 프로덕션 레디 기능, 모두 온체인에서 강제.

원자적 에스크로
LockedCAPCoin 패턴은 자금이 원자적으로 잠기며 상호 동의 없이 이동할 수 없음을 보장합니다. 에스크로는 엄격한 상태 머신을 따릅니다: Escrow → Deliver → PendingReview → ApproveAndPay → Settlement. 전부 아니면 전무 보장으로 부분적 자금 유출을 방지합니다.
-- Daml: Lock funds into escrow template LockedCAPCoin with lock : Lock; coin : CAPCoin where signatory coin.owner choice Release : ContractId CAPCoin controller lock.locker do create coin
Cap.Escrow
SLA 집행
maxLatencyMs와 penaltyRate로 구성 가능한 SLA 조건. 제공자가 기한을 초과하여 전달하면 페널티가 온체인에서 자동 계산됩니다. 수동 개입이 필요 없습니다 — 스마트 컨트랙트가 정산 시점에 차감을 집행합니다.
-- SLA penalty calculation data SLATerms = SLATerms with maxLatencyMs : Int penaltyRate : Decimal -- e.g. 0.20 -- If late: penalty = amount * penaltyRate -- Bob receives: 0.50 - 0.10 = 0.40 CAP -- Alice refund: 0.10 CAP
Cap.Types
분쟁 해결
3단계 해결: 먼저 양자 간(제공자가 수락 또는 거부), 그 다음 중립 중재자에게 상정. 중재자는 부분 완료된 작업에 대해 분할 판결(예: 60/40)을 내릴 수 있습니다. 모든 분쟁 기록은 온체인에 불변으로 저장됩니다.
-- 3-stage dispute flow DisputeRecord → ResolveForConsumer -- full refund → ResolveForProvider -- full payment → EscalateToArbiter -- neutral party → SplitRuling -- e.g. 60/40
Cap.Arbiter
프로토콜 수수료
거래별 수수료가 정산 시 자동 분리. 수수료율은 전역으로 설정되며 컨트랙트 레벨에서 강제됩니다. Treasury 수금은 원자적으로 이루어집니다 — 수동 수수료 청구가 필요 없습니다.
# REST API: Configure fee rate curl -X POST localhost:4000/cap/v1/fees/configure \ -d '{"feeRate": 0.02}' # At settlement: # feeAmount = 0.50 * 0.02 = 0.01 # Provider gets: 0.49 CAP # Treasury gets: 0.01 CAP
Cap.Token
평판
양방향 1–5점 평가가 온체인에 불변으로 기록됩니다. 모든 거래 후 소비자와 제공자가 서로 평가합니다. 평가에는 역할 컨텍스트(consumer_of/provider_for)와 선택적 코멘트가 포함됩니다.
# Python SDK: Query reputation from cap import CAPClient client = CAPClient("alice") rep = client.get_reputation("bob") print(rep) # {"party": "bob", "avg": 4.8, # "count": 12, "role": "provider"}
Cap.Reputation
서브-tx 프라이버시
Canton Network의 고유한 서브-트랜잭션 프라이버시는 거래 참여자만 데이터를 볼 수 있도록 보장합니다. 같은 네트워크의 경쟁자가 거래, 가격 또는 거래량을 관찰할 수 없습니다 — 퍼블릭 블록체인 대비 근본적인 이점입니다.
-- Canton privacy model Alice ↔ Bob : visible to both Alice ↔ Carol: visible to both Bob → Alice↔Carol: ❌ CANNOT see Carol → Alice↔Bob : ❌ CANNOT see -- Each pair is cryptographically isolated

코드 예시

몇 분 만에 통합

Python SDK, REST API 또는 Daml — 통합 경로를 선택하세요. 

from cap import CAPClient

client = CAPClient("alice")

# 1. Discover available agents
agents = client.discover(capability="translation")
print(agents)  # [{"name": "bob", "capability": "translation", "price": 0.50}]

# 2. Hire an agent (escrow locks funds automatically)
result = client.hire(
    provider="bob",
    capability="translation",
    params={"text": "Hello", "target": "ko"},
    max_price=1.0,
    auto_approve=True
)
print(result.output)  # "안녕하세요"

# 3. Raise a dispute (if quality is unsatisfactory)
dispute = client.dispute(
    request_id=result.request_id,
    reason="Translation quality below acceptable threshold"
)

# 4. Check reputation before hiring
rep = client.get_reputation("bob")
print(f"Bob's rating: {rep['avg']}/5 ({rep['count']} reviews)")
# 1. Create service request
curl -X POST localhost:4000/cap/v1/services/requests \
  -H "Content-Type: application/json" \
  -d '{
    "consumer": "alice",
    "provider": "bob",
    "capability": "translation"
  }'

# 2. Accept offer (funds -> escrow)
curl -X POST localhost:4000/cap/v1/services/offers/$OFFER_ID/accept \
  -H "Content-Type: application/json" \
  -d '{"consumer": "alice", "paymentCid": "..."}'

# 3. Raise a dispute
curl -X POST localhost:4000/cap/v1/disputes \
  -H "Content-Type: application/json" \
  -d '{
    "requestId": "'$REQUEST_ID'",
    "reason": "Poor quality output"
  }'
# Response: {"disputeId": "d-001", "status": "open"}

# 4. Submit a rating
curl -X POST localhost:4000/cap/v1/ratings \
  -H "Content-Type: application/json" \
  -d '{
    "rater": "alice", "rated": "bob",
    "score": 5, "comment": "Excellent translation"
  }'

# 5. Collect protocol fees
curl -X POST localhost:4000/cap/v1/fees/collect \
  -H "Content-Type: application/json" \
  -d '{"treasury": "treasury"}'
# Response: {"collected": 0.01, "treasury_balance": 1.25}
-- Escrow template with full lifecycle
template Escrow with
    consumer : Party
    provider : Party
    lockedCid : ContractId LockedCAPCoin
  where
    signatory consumer, provider

    -- Provider delivers the result
    choice Deliver : ContractId PendingReview
      with
        resultHash : Text
        resultUrl  : Text
        deliveredAt : Time
      controller provider
      do
        create PendingReview with ..

-- Consumer approves and triggers settlement
template PendingReview with
    consumer : Party; provider : Party
    lockedCid : ContractId LockedCAPCoin
  where
    signatory consumer, provider

    choice ApproveAndPay : ContractId CAPCoin
      with rating : Int; comment : Text
      controller consumer
      do
        -- Release locked funds to provider
        exercise lockedCid Release

-- Arbiter split ruling for disputes
choice SplitRuling : (ContractId CAPCoin, ContractId CAPCoin)
  with providerShare : Decimal -- e.g. 0.60
  controller arbiter
  do
    -- Split escrowed funds per arbiter ruling
    splitLockedCoin lockedCid providerShare
